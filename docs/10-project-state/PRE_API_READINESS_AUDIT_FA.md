# ممیزی آمادگی پیش از اتصال API

**نسخه 1.1.0** · ۱۴۰۵/۰۶/۱۴ (2026-09-05) · شاخه `codex/phase-2-decision-engine`

این سند یک توضیح مدیریتی ساده است. مرجع جزئیات فنی همچنان `CURRENT_STATE.md` و
مرجع کار بعدی `NEXT_TASK.md` است. «آمادهٔ محلی» در این سند به معنی «آمادهٔ توصیهٔ
مالی واقعی» نیست.

## نتیجهٔ کوتاه

- بخش محلی و مستقل از API پولی در محدودهٔ پذیرفته‌شدهٔ Phase 1: **۱۰۰٪**.
- برآورد موقت پیشرفت تا اولین نسخهٔ واقعی قابل اتکا: **حدود ۶۳٪**.
- برنامه، PostgreSQL، ذخیرهٔ سبد، زنجیرهٔ منشأ، دفتر سهمیه، پشتیبان، بازیابی، بررسی
  سلامت و راه‌اندازی یک‌مرحله‌ای روی رایانهٔ مالک کار می‌کنند.
- دادهٔ واقعی تاریخی، تأیید دو منبع ایرانی، روش مالی، بک‌تست، ورود تولیدی و استقرار
  قابل اتکا عمداً قفل هستند.
- فعلاً هیچ خرید، تماس، پایش پاسخ فروشنده یا ورود کلید جدید لازم نیست.

درصد ۶۳٪ یک **برآورد مدیریتی** بر اساس دروازه‌های زیر است، نه ادعای دقت مهندسی یا
زمان‌بندی. دامنهٔ Phase 2 هنوز باید با دادهٔ واقعی و تصمیم‌های مالی مالک نهایی شود.

## دقیقاً چه چیزی ادامه را باز می‌کند

در مرحلهٔ نهایی API، ابتدا باید شرایط کتبی منبع اصلی و منبع مستقل ایرانی بررسی شود:
حق استفاده و نگهداری تاریخچه، محدودهٔ تاریخ، نمادها، واحد قیمت، سقف درخواست، هزینه و
محدودیت‌های استفاده. سپس فهرست دقیق سرویس و پلن پیشنهادی برای خرید به مالک ارائه
می‌شود. کلیدها فقط از مسیر امن محلی وارد می‌شوند، نه چت و Git.

پس از آن، ترتیب کار تغییر نمی‌کند:

1. یک اتصال بسیار محدود و بدون ثبت رمز آزمایش می‌شود؛
2. تاریخچه فقط در محدودهٔ مجاز و بدون پر کردن ساختگی فاصله‌ها دریافت می‌شود؛
3. نتیجه با منبع مستقل ایرانی مقایسه و کیفیت آن ثبت می‌شود؛
4. فقط پس از قبولی Data Foundation، طراحی روش مالی برای تأیید مالک ارائه می‌شود؛
5. بک‌تست، walk-forward، حالت سایه و امنیت تولیدی باید جداگانه قبول شوند؛
6. آن‌گاه نسخهٔ واقعی می‌تواند برای تأیید نهایی آماده شود.

## نتیجهٔ ممیزی

`PASS` برای نسخهٔ محلیِ ارزیابی و کارهای مستقل از API در Phase 1.

`BLOCKED BY DESIGN` برای داده و تصمیم مالی واقعی. این قفل کمبود کد یا نیاز به پرامپت
جدید نیست؛ از ورود دادهٔ بدون مجوز یا توصیهٔ مالی آزمایش‌نشده جلوگیری می‌کند.
