# Rotation Engine

**Source of truth for:** the requirement to propose concrete portfolio actions.
Not implemented in Phase 0.

## Requirement

Given the gap between a current portfolio (`PORTFOLIO_MODEL.md`) and a proposed
allocation (`ALLOCATION_ENGINE.md`), the system must eventually be able to propose
concrete rotation actions:

- **Increase** a position
- **Reduce** a position
- **Hold** a position
- **Sell** a position
- **Convert** asset A into asset B (accounting for conversion cost — see
  `PORTFOLIO_MODEL.md` § transaction/conversion costs)

Each proposed action must come with its reasoning: which of the analysis
dimensions in `PORTFOLIO_MODEL.md` (valuation, risk, liquidity, regime, expected
return, cost, constraints) drove it.

## Owner-Approved Output Taxonomy

The owner has approved three presentation layers for future decision support:

1. **Homogeneous decision** — compare alternatives only within the current
   asset's class.
2. **Heterogeneous decision** — evaluate conversion from one asset class to
   another, including conversion costs and portfolio consequences.
3. **Best overall action** — evaluate the whole portfolio and market/data state
   together before presenting the best permitted action.

Phase 1 implements the labelled UI structure and deterministic readiness gates. The
Phase 2 demo now mirrors ADR 0010's laboratory-only target and action rules with
visibly synthetic inputs. Real target selection, thresholds and actions remain
locked until Iranian validation and a later production approval.

## Non-Negotiable Constraints

- Rotation logic is deterministic, code-computed from validated inputs — never
  generated by an LLM. The AI layer may explain a rotation proposal in natural
  language, but does not decide it. See `docs/06-ai/AI_ROLE.md`.
- This is decision **support**, not autonomous execution — no action is ever taken
  on the owner's behalf without their explicit review and approval (see
  `docs/06-ai/AI_ROLE.md` for the advice-vs-support boundary).
- Not used operationally until validated per
  `docs/03-market/HISTORICAL_ANALYSIS.md` and `docs/00-governance/QUALITY_GATES.md`.
