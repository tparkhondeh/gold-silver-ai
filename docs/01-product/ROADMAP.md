# Roadmap

**Source of truth for:** phase sequencing. This document tracks *order and status*
of phases, not their detailed content — each phase's real scope is defined and
approved at its own DESIGN step (`docs/00-governance/DEVELOPMENT_WORKFLOW.md`), not
pre-committed here.

## Principle

Phases proceed sequentially and are not started early
(`docs/00-governance/STABILITY_POLICY.md`). This roadmap shows the logical
dependency order implied by the project mission — later phases depend on earlier
ones being validated, not just built.

## Phases

| Phase | Focus | Status |
|---|---|---|
| Phase 0 | Foundation, governance, documentation architecture | **Owner-approved**; branch remains separate from `main` |
| Phase 1 | Data foundation plus a visible Persian local interface, scoped by ADR 0001 | **Owner-accepted for progression** on `codex/phase-1-data-ui`; not merged to `main` |
| Phase 2 | Isolated synthetic-only deterministic financial laboratory, scoped by ADR 0009 | **Active** on `codex/phase-2-decision-engine` |
| Phase 3+ | `STATUS: TBD` | Not started |

ADR 0009 scopes Phase 2 only as a synthetic, non-operational laboratory. The later
logical dependency order remains licensed data → historical/bubble analysis →
backtesting and Iran-specific calibration → portfolio/risk methodology → agent
layer. `DECISION REQUIRED: YES` from the owner before any real methodology is selected
or a later dependent phase is scoped.

## Proposed route to the first owner-operational release

بازبینی ۲۰۲۶-۰۹-۰۹: این مسیر از نیازهای ثبت‌شده استخراج شده است؛ تأیید فازهای
۳ به بعد، مجوز توسعه در نوبت ممیزی، یا وعدهٔ تاریخ تحویل نیست. وضعیت رسمی فازها
در جدول بالا تغییر نکرده است. R1 تا R8 شناسهٔ تحویل پیشنهادی‌اند، نه شمارهٔ فاز.
«پایان» در این نقشه، اولین نسخهٔ کامل و قابل‌اتکای مالک در محدودهٔ مصوب است؛ نه
پایان نگهداری نرم‌افزار یا توسعه‌های آینده. دامنهٔ نسخهٔ اول باید با معیارهای
پذیرش قابل‌شمارش بسته شود؛ هیچ قابلیت ثبت‌شده‌ای بدون تصمیم مالک حذف نمی‌شود.

به‌روزرسانی پس از مجوز اجرای مالک در همین تاریخ: راه‌اندازی لوکال و پیاده‌سازی R1
انجام شد؛ [راهنمای آزمون](../09-operations/OWNER_DECISION_TEST_FA.md) آمادهٔ مالک است.
قدم توسعهٔ پیشنهادی بعدی، R2 و بستن شکاف‌های زنجیرهٔ تحلیل روی همین ورودی است؛
این یادداشت مجوز انتشار یا شروع استفاده از دادهٔ واقعی نیست.

| R8 — پذیرش و انتشار نسخهٔ پایدار | R1–R7 و بسته‌شدن موارد ضروری نسخهٔ اول | آزمون کامل ورود داده ← تحلیل ← مقدار/قیمت/هزینه/افق ← نمایش ← ذخیره/بازیابی؛ خطا، قطع سرویس، بازیابی و کنترل دسترسی؛ هر سه CI روی Commit نهایی؛ آزمون فارسی مالک و تأیید کتبی؛ سپس انتشار نسخهٔ ثابت با پایش و برگشت آزموده | فهرست نهایی نیاز↔کد↔تست↔پذیرش هنوز بسته نیست؛ انتشار صرف یا تعداد تست ملاک پایان نیست؛ خطای بحرانی باز نباید باقی بماند | پذیرش نهایی محصول، اجازهٔ جداگانهٔ merge به main و انتشار پایدار؛ مجوز معاملهٔ خودکار جزو این پذیرش نیست |

مسیر اصلی محصول: R1 → R2 → R5 → R6 → R7 → R8. آماده‌سازی R3 و سپس R4 می‌تواند
از بخش‌های مستقل مسیر اصلی جدا پیش برود، اما انتقال اطلاعات شخصی قبل از R3
ممنوع است. R4 برای نمایش نسخهٔ فعلی لازم نیست منتظر خرید API بماند و جای R5/R6
را نمی‌گیرد. قراردادها و آزمون‌های ساختگی R7 نیز پس از R2 قابل‌آماده‌سازی‌اند؛
اتصال مدل و انتقال اطلاعات به تأیید مربوط وابسته است. هیچ گام بعدی مجاز نیست
یک پیش‌نیاز بحرانیِ ردشده را نادیده بگیرد.

### تعریف پذیرش خروجی موتور و پایان نسخهٔ اول

- هر دارایی و کل سبد: افزایش/ورود، کاهش/خروج، تبدیل هم‌کلاس و بین‌کلاسی، بدون
  تغییر، انتظار مشروط و تصمیم‌ناپذیر؛ قیمت یا شرط معتبر، مقدار فیزیکی، مبلغ،
  درصد با مخرج روشن، هزینه، نقد و ترکیب قبل/بعد، افق و دلایل عددی، ابطال و بازبینی.
- تحلیل کوتاه‌مدت و میان‌مدت مستقل دیده شود، ولی فقط یک برنامهٔ نهایی سازگار با
  سرمایه، بودجهٔ ریسک و محدودیت‌ها صادر شود. گزینه‌های جایگزین و تعریف ریاضی
  معیار انتخاب روشن باشد؛ قیمت دقیق به معنی سود تضمینی یا پیش‌بینی قطعی نیست.
- همهٔ نیازهای ضروری نسخهٔ اول به کد، قرارداد، تست و نتیجهٔ پذیرش وصل باشند؛
  یک تصمیم از ورودی نسخه‌دار تا نمایش و سابقهٔ ذخیره‌شده قابل‌بازتولید باشد.
- داده و روش واقعی جداگانه پذیرفته شوند؛ امنیت، پشتیبان/بازیابی، پایش، راهنمای
  استفاده و پشتیبانی عملیاتی آزموده باشند؛ مالک همان نسخهٔ نهایی را تأیید کند.
- شاخهٔ پایدار فقط با مجوز مالک تغییر کند. معاملهٔ خودکار، کاربران دیگر، کانال
  جدید یا توسعهٔ دارایی‌های خارج محدوده، پایان این نسخه را بی‌دلیل گسترش نمی‌دهند.

درصد کل فقط پس از ثبت مخرج کاملِ معیارهای پذیرش و شواهد قبولی قابل گزارش است.
تعداد تست‌ها و قبولی هشت معیار میز، مخرج کل محصول نیستند. زمان پایان اکنون
قابل تعهد نیست؛ مجوز داده، کیفیت واقعی، امنیت و بازخورد پذیرش وابستگی بیرونی‌اند.
